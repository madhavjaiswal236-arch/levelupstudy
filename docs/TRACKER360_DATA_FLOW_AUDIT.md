## 2. THE 9 TASK CREATION & COMPLETION PATHWAYS (DETAILED TRACE)

### Pathway A: Task Automatically Generated by Tracker 360
- **Creation:** In `src/pages/BacklogHQ.tsx:L280-L340`, calling `handleGeneratePlan()` iterates through `selectedChapters` and produces planned day slots.
- **Persistence:** Writes to `localStorage.setItem('levelup_backlog_v2', ...)`.
- **Divergence:** It does **NOT** append items into `AppContext.todos`. The user sees tasks in Backlog HQ, but when viewing the primary Dashboard task list, these backlog tasks do NOT appear unless explicitly imported.
- **Completion:** Ticking a task inside Backlog HQ toggles `item.isCompleted` in Backlog HQ local state. It never fires `addXp()`, never increments `questionsSolved`, and never updates `syllabus`.

### Pathway B: Task Manually Created by User
- **Creation:** In `src/pages/Dashboard.tsx:L1200` or `src/pages/Tasks.tsx`, user enters title and clicks "Add Task". Calls `addTodo({ text, category, priority, dueDate })`.
- **Persistence:** Added to `AppContext.todos` array. Debounced save writes entire state to Firestore `/users/{uid}`.
- **Completion:** Clicking checkbox calls `toggleTodo(id)`. Flips `completed: !t.completed`. Calls `addXp(t.xp || 50)`.
- **Divergence:** If the task text matches a chapter name, it has no foreign key `chapterId`. As a result, completing manual tasks has **zero impact** on syllabus progress.

### Pathway C: Task Edited After Creation
- **Action:** User edits title, priority, or tags in `Tasks.tsx`.
- **State Update:** Updates `todos` array in place.
- **Divergence:** Editing does not validate or re-link to syllabus metadata. If a completed task is edited, it preserves `completed: true` without idempotency validation.

### Pathway D: Task Marked Complete from Dashboard
- **Action:** Checked in `Dashboard.tsx` under "Today's Tasks".
- **Handler:** `toggleTodo(id)`.
- **Outcome:** Awards XP. Increases dashboard completed count. Triggers confetti.
- **Divergence:** Does not check off corresponding lectures in `Syllabus.tsx`.

### Pathway E: Task Marked Complete from Task Management Screen
- **Action:** Checked in `Tasks.tsx`.
- **Handler:** `toggleTodo(id)`. Identical handler to Pathway D.
- **Divergence:** Filters on category or date in `Tasks.tsx` can cause visual desync if filtered lists maintain separate local state slices before parent re-renders.

### Pathway F: Task Marked Complete from Study Plan Queue
- **Action:** Checked in `StudyPlanQueue.tsx` (middle section of Dashboard).
- **Handler:** Calls `toggleTodo(id)`.
- **Divergence:** If the task was injected by AI Coach recommendations, `coachEngine` does not receive notification that its recommendation was accepted and fulfilled.

### Pathway G: Task Marked Complete from Chapter or Syllabus Screen
- **Action:** Checked in `Syllabus.tsx` or `ChapterDetailModal.tsx`.
- **Handler:** Directly mutates `syllabus[subjectIndex].chapters[chapIndex].lectures[lecIndex].completed = true`.
- **Outcome:** Recalculates chapter percentage: `(completedLectures / totalLectures) * 100`.
- **Divergence:** **CRITICAL DEFECT.** It does NOT invoke `addXp()`. It does NOT mark any existing `todo` complete. The user finishes an entire chapter of lectures but gains 0 XP on their dashboard.

### Pathway H: Work Logged Through JEE Logger
- **Action:** In `JeeSessionLogger.tsx`, student logs 45 questions solved with 38 correct in 60 minutes.
- **Handler:** `logSession()`. Calls:
  - `setQuestionsSolved((prev) => prev + validAttempted)`
  - `addXp(calculatedSessionXp)`
  - Appends to `practiceSessions`.
- **Divergence:** Does NOT mark any pending "Solve 30 Questions" tasks in `todos` as completed. Daily question count increases, but the task remains pending.

### Pathway I: Adaptive Coach Dynamic Missions
- **Action:** Mission recommended by `src/lib/coach/coachEngine.ts` (e.g., "Revise Thermodynamics formulas").
- **Handler:** `completeMission(missionId)` in `CoachContext.tsx`.
- **Divergence:** Purely in-memory state. Awards XP in local state, but because it is not recorded in `todos` or `history`, a page refresh wipes out the completed mission and reverts XP if cloud sync has not executed.

## 4. AUTHORITATIVE DATA SOURCES VS DERIVED VALUES

| Data Point | Current Implementation | Flaw | Authoritative Design Target |
| :--- | :--- | :--- | :--- |
| **Questions Solved Today** | Stored primitive: `questionsSolved` in `AppContext` | Incremented blindly by disparate functions; latched by `Math.max()` in sync | Derived at runtime: `SUM(sessions.attempted WHERE date == today)` |
| **Chapter Mastery %** | Stored inside each chapter in `syllabus` | Out of sync with `todos` and backlog items | Derived: `(completedLectures / totalLectures) * 100` via verified lecture ID set |
| **Total XP** | Stored primitive: `xp` in `AppContext` | Non-idempotent; repeated toggles re-award XP indefinitely | Derived or Ledger-based: `SUM(xpTransactions.amount)` with unique `idempotencyKey` |
| **Active Tasks** | Array of objects in `todos` | No foreign key to syllabus chapters; backlog creates duplicate isolated tasks | Normalized collection `/users/{uid}/todos` with optional `chapterId` and `source` |
| **Daily Target** | Stored primitive: `dailyTarget` | Inadvertently overwritten with 2400 from 8hr XP target | Strict numeric field validated to range `[10, 500]` questions/day |
